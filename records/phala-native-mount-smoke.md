The test created a local Docker named tmpfs volume with the launch document's `uid=0,gid=0,mode=1775` options and a separate local public-state volume. While that quote container remained running, the app identity (`10001:0`) read and updated a group-writable marker in the same tmpfs, found no usable dstack socket in its own mount namespace, observed a non-tmpfs public-state volume owned by UID 10001, and wrote to that state volume and `/run`. The script removed its test-owned container and volumes; the runner step exited successfully.

The first, sequential version of this probe [failed](https://github.com/tamnys/ZECret-service/actions/runs/36690979577) because no container held the tmpfs volume between the two runs. The final probe keeps the quote container alive, as the Compose design intends with `depends_on: service_healthy`. This finding makes concurrent lifetime a requirement for the shared memory volume. It does not prove Phala's actual Compose mount behavior, quote-socket access, service restart handling, snapshot import, Zebra/wrapper operation, full guest resource fit, or a TDX attestation. Those remain hardware or complete-service tests. The stock Phala guest still does not satisfy genuine private-mode requirements.

## Actual quote-service mount correction

The first probe's app isolation observation was incomplete: it checked the shared runtime before starting the actual quote service. When the packaged quote service later mounted a root-owned synthetic backend at `/run/dstack.sock` in the quote container, the app saw that socket through the shared tmpfs. [Run 36701303221](https://github.com/tamnys/ZECret-service/actions/runs/36701303221) failed on the app's negative assertion. The fact that the Compose text assigned the bind only to `quote` did not establish mount isolation.

The corrected stock profile binds the host source `/run/dstack.sock` at `/dstack.sock` in the quote container, outside the shared `/run` volume. The native Rust artifact from [run 36702475575](https://github.com/tamnys/ZECret-service/actions/runs/36702475575) contains a twice-matching x86_64 quote proxy compiled for that exact target.
