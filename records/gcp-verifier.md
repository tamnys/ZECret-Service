# GCP TDX verifier checkpoint

This record describes implementation and local validation. It is not a
production release approval, a Google hosting assertion, or evidence that the
candidate guest has booted on TDX hardware.

## Implemented boundary

The GCP v1 envelope is separate from the unchanged Phala envelope. It carries
`platform: "gcp-tdx"`, `schema_version: 1`, the nonce echo, raw Intel quote hex,
and binary CCEL hex. Parsing rejects cross-provider evidence, unknown versions,
duplicate/unknown fields, malformed hex, and bodies exceeding the existing
protocol response limit. The nonce echo itself grants no freshness authority.

`inspect_gcp_workload_and_report_data` reaches signed report data and workload
comparisons only through the existing offline DCAP QVL callback, after Intel
authentication and strict TCB appraisal. It uses supplied collateral and the
system clock, with no fetch client or alternate verification root.

The CCEL decoder supports the crypto-agile `Spec ID Event03` format and selects
SHA-384 by its TPM algorithm identifier. It validates declared digest sizes,
rejects duplicate/unknown banks, checks all lengths before slicing, and maps CC
MR indices 1–4 to RTMR0–3. Replay starts with zeroed registers and uses the
existing maintained SHA-384 implementation. Uniform zero/FF suffix padding is
accepted; hidden data following a padding marker is not ignored. No firmware
replay workaround or missing-register exception is applied.

RTMR replay does not authenticate event types or descriptions. GCP policy
therefore requires the complete ordered reference sequence, each measured
digest, each descriptor's SHA-256, and the Spec ID header reference. Event types
whose data is directly hashed also require a content-to-measured-digest match.
The selected UKI event must be an EFI boot-services application in RTMR1 and
must match the explicit UKI PE/COFF SHA-384 reference, not a whole-file SHA-384.

The policy also records firmware-endorsement, UKI, rootfs-verity, command-line,
boot-policy, wrapper, Zebra, quote-broker, and measurement-recipe identities.
These reference fields do not themselves reconstruct a boot measurement or
prove that an arbitrary supplied artifact contains another artifact. That
relationship must be established independently during release review.

`ApprovedRelease` now holds provider-specific manifests. GCP schema v2 has no
Phala Compose/container/KMS placeholders. A diagnostic policy cannot create an
approved release; the packaged release catalog remains empty. Diagnostic
agreement also cannot create a retained TLS session. Transport authorization
additionally owns the exporter-bound connection, clocks, collateral expiry,
and packaged release selection.

## Source and fixture provenance

- [Google measurement-register contents](https://docs.cloud.google.com/confidential-computing/confidential-vm/docs/measurement-register-contents)
  identifies MRTD and TDX RTMR responsibilities; vTPM measurements are not the
  hardware trust root used here.
- CCEL framing and index mapping were checked against
  [google/go-eventlog, commit 65d54cb8f3fb1a6ccb3f0a0a6e247e5c13a4bc04](https://github.com/google/go-eventlog/tree/65d54cb8f3fb1a6ccb3f0a0a6e247e5c13a4bc04),
  specifically `tcg/pfpformat.go`, `ccel/cceventlog.go`, `ccel/replay.go`, and
  `register/rtmr.go`.
- `tests/fixtures/gcp/cos-113-intel-tdx.bin` is the upstream COS113 CCEL fixture,
  SHA-256 `090dc18758380a5cc03014bf2fe354788a4f4222671e1e38f85b772d2fd344b5`.
  Its replay is compared with the upstream `COS113TDX` expected-register vector.
  Its Apache-2.0 license and provenance are retained beside the fixture. This
  is an old GRUB-based compatibility vector, not the project's UKI guest.
- `policy.synthetic.json` and `ccel.synthetic.bin` are generated by the included
  standard-library Python generator. Rust tests independently construct and
  compare the same synthetic values. Every artifact identity is fabricated for
  parser/comparison testing and is never entered into the release catalog.

## Local validation

The root agent ran the focused protocol, verifier, and transport tests through
the managed browser container with locked Cargo dependencies. They passed.
GCP coverage includes:

- Explicit provider/version framing and rejected unknown/duplicate fields.
- Pinned upstream CCEL hash and replay-vector agreement.
- Every truncated synthetic log prefix, oversized lengths, unsupported MR
  indices and banks, incorrect digest sizes, malformed padding, and hidden tails.
- Changed event types and descriptions that preserve RTMR replay.
- Changed measured variable data despite a matching forged descriptor reference.
- Changed signed MRTD or any RTMR, wrong UKI binding, and missing artifact
  commitments.
- Authentic historical quote rejection under strict TCB policy before GCP
  comparisons, plus fabricated matching measurements failing authentication.
- GCP release-manifest isolation from Phala fields and the empty approval list.

No hardware acceptance was performed by these tests. Google fixture replay is
comparison-only: no authenticated quote/collateral tuple accompanies that log.

## Remaining release gates

1. Independently verify the selected Google firmware endorsement and reconstruct
   expected MRTD/boot measurements from the exact firmware, signed UKI, rootfs,
   and configuration. Do not extract an approval policy from a first-seen quote.
2. Validate the entire UKI/rootfs/configuration relationship and mutable-input
   exclusions. Exact descriptor matching is intentionally restrictive: variable
   firmware descriptors that cannot be independently reconstructed currently
   reject. Do not add masks or ignored events without a reviewed measurement
   interpretation and negative tests.
3. Exercise the exact production artifact on real TDX and satisfy the guest,
   administration, disk, key-ownership, freshness, and cleanup gates. Complete
   the existing TLS-exporter construction's security review.
4. Package a reviewed provider-specific manifest in a native-client release only
   after those gates pass. Google project/zone/instance provenance is not
   separately appraised by this implementation and must not be displayed as
   independently verified.
