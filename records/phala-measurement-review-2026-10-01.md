# Phala-trusting release review, 2026-10-01

This record approves `phala-prod9-testnet-20261001-1` only under the user's explicit trust in Phala's managed guest, runtime, and KMS. It does not approve the stricter provider-independent private mode. The approved native client embeds the release manifest; the external selection policy can only select it. No customer wallet data was used in acceptance.

## Live acceptance and rejection

The native client used the local Tor executable, offline collateral, Intel quote verification, event-log replay, release matching, fresh nonce, and TLS-exporter binding on the retained connection. `zrpc verify --privacy-profile phala-trusted` returned `phala_trusted_authorized: true`, `query_sent: false`, and `private_accepted: false` (the last field refers to strict private mode). Supplying the earlier candidate Compose to `zrpc query --method getblockchaininfo` rejected the request with `query_sent: false`. Supplying the pinned launch configuration returned live testnet chain status at height 4,428,723. A query for the repository's synthetic testnet address returned `balance: 0, received: 0` over the verified connection. No wallet keys, customer addresses, or payments were used.

The stock image still permits provider-managed runtime persistence and administrative mechanisms. The image does not prove the original disk-isolation or no-guest-administration properties. This release therefore uses only the named Phala-trusting profile and must never populate the provider-independent `ApprovedRelease` catalog. A changed image, launch configuration, KMS identity, quote, event log, or TLS key must require a new review and packaged client release. The live CVM remains billable until all attached resources are deleted; the experiment ledger and deletion deadline remain controlling.
