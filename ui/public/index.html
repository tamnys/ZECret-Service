End-to-end private ZCash queries

Fully shielded Zcash transactions hide payment details on-chain. A direct RPC connection can still reveal your IP address and the blocks or transaction IDs you request. ZECret is designed to route queries through Tor and verify the service first.

How ZECret is designed to work

  1. Connect through TorThe service does not see your direct IP address.
  2. Verify the serviceThe client checks its release, attestation, and connection.
  3. Make a read-only queryThe verified service handles one request.

Privacy model

Two different checks.

The network route and the software answering the request need separate protection.

Tor hides the direct route.

The native client uses Tor so the service does not see the client's direct network address. It does not anonymize this website visit or prevent every form of traffic analysis.

Attestation checks the service.

The native client checks evidence about the remote workload and binds that check to its live TLS connection before sending query parameters. A badge on this page cannot make that decision.

For developers

Run the native client locally.

The current Rust CLI includes local synthetic examples. Build from source on Linux with the pinned Rust 1.94.1 toolchain and committed Cargo.lock.

These commands do not start a verified private session. There is no approved release download or checksum to link yet.

Supported read-only methods

  • getblockchaininfo
  • getblockcount
  • getblockhash
  • getblockheader
  • getrawtransaction

Wallet methods, transaction submission, batches, and arbitrary upstream URLs are rejected. Requests with parameters use the native client's typed format.

Proposed payment model

Prepaid credits would stay with the client.

The proposed flow is to buy a batch, keep blinded one-use tickets locally, and spend one when a request is admitted. It would avoid an on-chain transaction for every query.

For this experiment, settlement would be a private operator file exchange. Issuance and redemption are not implemented, and this site accepts no ZEC payment. A ticket could be consumed even if the node fails or the response is lost; the client must not automatically spend a replacement.
