Privacy model · Experimental

Where privacy begins and ends.

The public demo shows fixed examples. For live Zcash testnet queries, the native client can verify and use the approved Phala-trusting release. The website itself does not make RPC queries.

Visiting this website

Cloudflare serves this public site and can observe ordinary visitor metadata, including network addresses and request timing. The application adds no analytics, identity cookies, accounts, third-party scripts, or request-body logging.

This site does not accept transaction selections, wallet material, tickets, or native-client secrets. It does not connect to localhost. Tor use by the native CLI does not anonymize a browser visit here.

The demo API returns fixed public examples. Its output cannot approve a release or verify a private query.

Using the native client

The approved path is native Rust client → Tor → attested TLS connection → measured RPC wrapper → loopback Zebra testnet node. Before sending query parameters, the client checks a packaged release, hardware and workload evidence, freshness, and the live encrypted connection.

This is the Phala-trusting profile: it also trusts Phala's guest administration, KMS, and persistent runtime controls. The stricter provider-independent private profile remains unavailable. The bundled local dashboard shares the native client core and does not take trusted release settings from this website.

Payment proof of concept

The separate native ticket proof of concept keeps blinding state and one-use tickets in a private client store. The issuer signs blinded requests without receiving finalized tickets. A ticket-required service records spent-ticket markers without purchase references or query contents.

The approved Phala-trusting testnet service does not accept tickets or ZEC payments. In the ticket demo, a credit is used when a request is admitted; a node error or lost response can still consume it. The client does not automatically spend a replacement.

Blinding does not remove timing, network, or small-crowd correlation. Ordinary restart safety does not protect against malicious disk rollback. This website does not handle tickets or payments.

Records and limits

The browser demo does not intentionally save query history or remote diagnostics. CLI output remains on the user's device. The local dashboard keeps its access capability in memory and serves API results with no-store headers.

The service is designed not to persist request bodies, transaction selections, responses, customer identifiers, or query-to-payment mappings. That is an application policy, not proof that browsers, operating systems, providers, or compromised software retain nothing.

Tor cannot defeat every form of traffic analysis. Attestation does not prove blockchain consensus or that software has no bugs. Your device, release distribution, verifier, hardware vendor, firmware, and accepted platform stack remain part of the trust model.
