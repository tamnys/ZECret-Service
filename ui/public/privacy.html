PRIVACY MODEL · EXPERIMENTAL

Know which part
you are trusting.

The public site teaches the model with fixtures. The native client is the component intended to verify a private connection. No approved private release or hosted endpoint is available through this site today.

01 / THIS WEBSITE

A public visit stays public.

Cloudflare serves this site and can observe ordinary visitor metadata such as network addresses and request timing. We do not add analytics, identity cookies, customer accounts, third-party scripts, or request-body logging in the application. The site does not accept transaction selections, wallet material, tickets, or local-client secrets. It does not connect to localhost.

Using Tor for the native CLI does not anonymize your browser visit here. The fixture API returns only fixed public examples and is never an approval authority.

02 / NATIVE CLIENT

Verification belongs on your device.

The intended private path is the native Rust client through Tor to an attested TLS connection, then a measured RPC wrapper and loopback Zebra testnet node. Before sending query parameters, the client must check an independently trusted approved release, hardware and workload evidence, freshness, and binding to the live encrypted connection. A status badge on this website cannot perform that verification.

The bundled local dashboard opens from the CLI and shares its Rust core. It is separate from this public site and does not silently inherit configuration from it.

03 / PROPOSED PAYMENTS

One-use tickets would stay local.

The planned prepaid model keeps pending purchases, blinding state, and unspent tickets in a private native-client store. A separate issuer would authorize blinded requests but never receive finalized tokens; a redeemer would keep issuer-scoped spent markers rather than purchase references or query contents. The initial proof of concept proposes simulated settlement via private operator file exchange. It has not been implemented and accepts no ZEC payments.

A ticket would be charged on admission. Node errors and lost responses could consume it; there are no automatic retries, refunds, or stored response replay in the proposal. Blinding does not remove timing, network, or small-crowd correlation, and ordinary restart safety would not protect against malicious disk rollback.

04 / RECORDS + LIMITS

Policy is not proof of deletion.

The current local fixture application does not intentionally save query history or remote diagnostics. CLI output remains on the operator’s device. The local dashboard keeps its access capability in memory and serves API results with no-store headers. A future approved wrapper is intended not to persist request bodies, transaction selections, responses, customer identifiers, or query-to-payment mappings. This is an application policy, not a claim that browsers, operating systems, providers, or compromised software retain nothing.

Tor does not defeat all traffic analysis. A TEE does not establish blockchain consensus, prove software has no bugs, or hide every access pattern. Your device, the release distribution, verifier, hardware vendor, firmware, and accepted platform stack remain in the trust model.
