Privacy model · Experimental

Where privacy begins and ends.

The public site explains ZECret Service with fixed examples. Only the native client is designed to verify a private connection. No approved private release or hosted endpoint is available through this site today.

Visiting this website

Cloudflare serves this public site and can observe ordinary visitor metadata, including network addresses and request timing. The application adds no analytics, identity cookies, accounts, third-party scripts, or request-body logging.

This site does not accept transaction selections, wallet material, tickets, or native-client secrets. It does not connect to localhost. Tor use by the native CLI does not anonymize a browser visit here.

The demo API returns fixed public examples. Its output cannot approve a release or verify a private query.

Using the native client

The intended path is native Rust client → Tor → attested TLS connection → measured RPC wrapper → loopback Zebra testnet node. Before sending query parameters, the client must check an independently trusted approved release, hardware and workload evidence, freshness, and the live encrypted connection.

The bundled local dashboard opens from the CLI and shares its Rust core. It is separate from this public site and does not silently take trusted release settings from it.

Payment proof of concept

The native payment proof of concept keeps pending purchases, blinding state, and one-use tickets in a private client store. The issuer signs blinded requests without receiving finalized tickets. The service records spent-ticket markers without purchase references or query contents.

Settlement currently uses a private file exchange with an operator and transfers no ZEC. No ticket-required private service is approved or available. A ticket is charged when a request is admitted, so a node error or lost response can consume it. The client does not automatically spend a replacement; this proof of concept has no refunds or stored response replay.

Blinding does not remove timing, network, or small-crowd correlation. Ordinary restart safety does not protect against malicious disk rollback. This website does not handle tickets or payments.

Records and limits

The current local fixture application does not intentionally save query history or remote diagnostics. CLI output remains on the operator's device. The local dashboard keeps its access capability in memory and serves API results with no-store headers.

A future approved wrapper is intended not to persist request bodies, transaction selections, responses, customer identifiers, or query-to-payment mappings. That is an application policy, not proof that browsers, operating systems, providers, or compromised software retain nothing.

Tor cannot defeat every form of traffic analysis. Attestation does not prove blockchain consensus or that software has no bugs. Your device, release distribution, verifier, hardware vendor, firmware, and accepted platform stack remain part of the trust model.
