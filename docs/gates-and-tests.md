# Acceptance checklist

## Local M0

- CLI and local dashboard use the same fixture client; every response labels simulation and refuses a private-acceptance claim.
- Strict read-only method/parameter parsing rejects batches, notifications, unknown fields, keys, write/admin methods and oversized requests.
- Private bootstrap cannot send RPC; synthetic evidence cannot yield a verified channel.
- Wrong release/key/nonce/event log, unavailable Tor and unavailable node have distinct fixture outcomes; verification rejection means no fixture query dispatch.
- Local APIs require a per-launch capability and exact loopback Host/Origin; reject missing credentials, foreign origins, rebinding hosts and unsupported methods.
- Bundled assets have no remote dependencies; outputs use text; no history or browser-to-cloud request path.
- Cost plan reproduces $40.84416, includes existing resources/fees, refuses over $50 projected; deadline ≤168 hours, delete decision at $45 or deadline. Stop is never deletion.
- Fake cleanup handles partial creation, retry and residual resources; deployment remains disabled.

## Gates required before a cloud privacy claim

- A: local Intel chain/collateral/TCB appraisal and authenticated workload/event-log reconstruction match independent policy.
- B: reviewed nonce/context/key encoding, live TLS possession, freshness and per-connection verification; no generic caller-key attestation.
- C: selected measured production image/config denies SSH, debug console, exec and mutable startup access.
- D: exact KMS/rootfs/disk authorization implications preserve code identity; persistent chain state cannot load executable/configuration content.
- E: authenticated available-resource quote, all fees and funding requirements, testnet memory/disk fit, proven external deletion and deadline controls.

M0 does not establish any live gate. See the feasibility record for sources and evidence still required.
